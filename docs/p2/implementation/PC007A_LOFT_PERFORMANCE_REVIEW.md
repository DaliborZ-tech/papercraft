## PF-01 — neaktuální stará reprezentace se tvářila fresh

**MEDIUM, původně CHANGES_REQUIRED na2e4; nyní CLOSED na7a4.** `_commands` zkrátil skutečný validní CUT, ale původní `ANALYTIC_SIGNED_CREASES_AND_INTRINSIC_AREA_V1` zůstal v input digestu i statusu. Načtený starý soubor proto měl `part.stale=false`, `paper_stale=false` a source EXACT, zatímco `validate_layout` už odmítal jeho správnou předchozí reprezentaci jako INVALID_CACHE. Snapshot se bezpečně blokoval — nešlo o nalezený exportní bypass — ale stav a běžný postup explicitního recompute byly nepravdivé.

Reprodukce není pouze syntetická: [skutečný803command Bézier raw](evidence/pc007a-loft-performance-review-real803-2e4.json), source file SHA **`d10ee1fd2470117dcf45e158b7986e1d1bb0f8c205512048b150c6e434c1ecf3`**, pochází z root nativního23ce202 průchodu. Nezávisle byl také v archivu předchozího10a21ac vytvořen nový validní439command soubor: [bytes](evidence/pc007a-loft-performance-review-before803.apcraft) a [výsledek načtení](evidence/pc007a-loft-performance-review-old-cache-2e4.json). Historický název tohoto reviewerova souboru obsahuje803, skutečný ověřený počet v něm je439; není zaměněn za původní skutečný803command model.

Oprava7a4 zavádí sdílený **`LOFT_PAPER_CONTRACT=ANALYTIC_SIGNED_CREASES_INTRINSIC_AREA_EXACT_COLLINEAR_CUT_V2`** pro digest, material-cache key a veřejný status. Reader po validaci označí loft s odlišným skutečným digestem jako stale; původní CUT a autorská data ponechá do výslovného přepočtu. Vlastní [closure raw skutečného803L modelu](evidence/pc007a-loft-performance-review-PF01-close-7a4.json) potvrzuje:

- Při load zůstává803 původních commands, `part.stale=true`, `paper_stale=true`, jediná layout issue STALE a snapshot blokovaný.
- Teprve explicitní recompute vytvoří5 M/L/Z commands. Profily, part UUID, frame, stránka/placement včetně locks i původní soubor zůstávají; potom issues[] a snapshot projde. Vlastní save do kopie/reopen má přesně stejný aktuální projekt.
- Aktuální digest není povolení libovolné stejné plochy: vlastní current cache s posunutým CUT po `from_dict` stále zůstane fresh vzhledem ke zdroji, ale dostane INVALID_CACHE a blokovaný snapshot. Recompute obnoví přesně původní validní data. Oprava tak neukryla poison za obecné stale nebo za přijetí jeho geometrie.

## Co bylo nezávisle potvrzeno

**Úplné actual-source klíče.** `_analysis_keys` obsahuje oba celé source profile records včetně jejich plane, segment data/UUID a obou skutečných revisions, dále scale a params; samostatný celý surface record obsahuje feature identity, pose a parent transforms. Nejde o globální revizi nebo revision-only úspěch. Vlastní změny obou plane origins i obou cubic controls bez zvýšení revize vyvolaly nové důkazy a správné analytické světové body. Přímá změna position,90° rotation, rigidního parent transformu a scale rovněž změnila klíč; neplatný stretch transform nemohl znovu použít dřívější validní proof.

**Stejná kontrola světa, méně kopií.** Nové world cache value je immutable JSON string, LRU má8 položek. `_build_world_mesh` stále provede původní přímé vyhodnocení zdroje a úplné world metric/area kontroly pro každý nový skutečný klíč; private validation používá tutéž `_world_mesh_json` cestu a pouze neparsuje kopii sítě. Public `world_geometry` vrací nové JSON decode hodnoty. Vlastní poškození vrácených vertices, boundary provenance a triangle/vertex metadata se nepřenáší do příštího výsledku ani projektu.

**Private readonly view neuniká.** `_analysis_readonly` je privátní konvence; review všech změněných call sites potvrdilo pouze čtení. Veřejné analysis a loft_status zůstávají deep detached, material geometry je z nové immutable JSON cache znovu oddělená. Mutace nested source certifikátu, status source_binding, crease role, part.frame, surface_ids, lineage, labels, edges a CUT z vrácených výsledků nepoškodila cache ani projekt.

**Kanonický materiál a skutečný cache payload.** Material LRU je také omezená8 položkami; klíč přidává skutečnou part identity/name, surface_ids, frame, front_side a sdílenou capability. Vlastní změna kotvy, strany potisku a názvu vytvořila nové správné výsledky, včetně obrácení mountain/valley. `validate_layout` stále porovnává všechny4 skutečné fields polygons/paths/labels/edges s očekávanou kanonickou geometrií. Odstranění zbytečného deepcopy nepřidalo pozitivní shortcut. Po dřívější úspěšné warm validaci byly samostatně poškozeny všechny4 fields; každý případ byl odmítnut a snapshot blokovaný. Stejnoplochá translace CUT se nepropašovala.

**Přesná kompakce.** Dvojice L se sloučí pouze uvnitř stejného skutečného source profile/segment, při shodném spojovacím bodu, přesném Fraction cross product0 a prokázané betweenness. To zachovává celou trasu i délku. Vlastní tři deterministické racionální monotónní chains ověřily celé endpointy i nemutovaný vstup;6 negativních tříd zachovalo zpětný chod, roh2^-60, jiný profile ID, jiný segment ID, chybějící source a přesně přímý C. Nepřidává se epsilon a C se nemění na L. Rulingy bez stejného source profile/segment se neslučují. Closing L může být reprezentované implicitním Z jako v původním contractu; oba skutečné rulingy a source metadata nadále zůstávají.

**Provenance a writer interface.** Skutečný803L Bézier si po pěti CUT commands zachoval podrobnou source parameter map v `native.patches[].first/second.segments`, více než100 úseků na každé straně, spojité intervaly0→1 i původní C source. Private signatury `_bound_analysis(key,surface_record)` a `_local_frame(project,part,result)` zůstávají. Vlastní odvození z detached snapshot source records právě touto dvojicí vrátilo stejné skutečné5command CUT a správnou feature identity/area certifikát. Nový3f4 loft writer není v tomto přesném branchi; tento test není falešné schválení jeho dosud samostatné společné integrace.
